## 📖 Project Overview

<div align="center">

### What is Personal Study Planner?

</div>

**Personal Study Planner** is a native Android application designed to help students and self-learners take full control of their study schedule, manage academic subjects, and monitor their own learning progress — all completely **offline**, with no internet connection required.

The application addresses a common but often overlooked problem: students struggle to stay organized across multiple subjects, often losing track of what they've studied, what remains, and how much time they've invested in each area. Generic calendar apps and to-do lists don't understand the nuances of academic study planning.

### 🎯 Who is it for?

| Audience | Use Case |
|---|---|
| 📚 Students | Managing multiple subjects, planning daily study sessions |
| 🎓 Self-Learners | Tracking personal learning journeys and goals |
| 📝 Exam Preppers | Organizing topics, tracking revision cycles |
| 💻 Developers | Learning Kotlin and Android development (project reference) |

### 💡 Why this project was created

This project was born from a practical need and a learning objective — to build a functional, real-world Android application that solves an everyday problem while mastering the complete Android development workflow: from **writing code** to **deploying on a physical device** and **debugging real runtime errors**.

### 📌 Current Development Status

The application has reached a working state:

- ✅ Core Android application successfully built
- ✅ Debug APK generated via Gradle
- ✅ Successfully installed and tested on a **physical Redmi 12 Android device**
- ✅ Runtime NullPointerException identified, debugged, and fixed
- ✅ Application launched and runs independently on the physical device
- 🔄 Additional features and enhancements actively planned

## 🎯 Project Vision

<div align="center">

*"From a simple offline study planner to a complete, cloud-powered personal study management platform."*

</div>

The long-term vision for Personal Study Planner is progressive and deliberate:

**Phase 1 — Offline Foundation**
Build a fully functional, offline-first Android app that works reliably without any internet dependency. Core study management features, clean navigation, and stable performance on real Android hardware.

**Phase 2 — Identity & Authentication**
Introduce user accounts through Firebase Authentication — allowing users to securely log in, sign up, recover passwords, and have a personalized experience tied to their identity.

**Phase 3 — Cloud Synchronization**
Migrate local data to Firebase Cloud services, enabling cross-device synchronization, automatic backups, and secure cloud storage of study data.

**Phase 4 — Intelligence & Insights**
Layer advanced analytics, study statistics, goal-setting, smart reminders, and progress insights on top of the cloud-connected foundation.

**Phase 5 — Production-Ready Polish**
Comprehensive testing, UI/UX refinement, performance optimization, and preparation for a production-quality release.

The project is being developed with a **clean, phase-by-phase approach** — building real foundations before adding complexity.

The application follows a structured, layered architecture approach appropriate for Android development:

```
┌─────────────────────────────────────────────────────────────┐
│                    PRESENTATION LAYER                        │
│           Screens / Fragments / Navigation                   │
│         Bottom Navigation Bar | Dashboard | Subjects         │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                     LOGIC LAYER                              │
│             ViewModels / State Management                    │
│          Study Sessions | Subject Data | Progress            │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                      DATA LAYER                              │
```

## 🚀 Development Journey

<div align="center">

### Build → Deploy → Debug → Fix → Rebuild → Test

*A real Android development lifecycle, documented.*

</div>

This section documents the authentic development and deployment journey for this project — from first build to a working app running on a physical Android device.

---

### 🔨 Step 1 — Project Build

The project was structured as a standard Android application using **Kotlin** and **Gradle**.

The build process was initiated using the Gradle wrapper:

```bash
./gradlew assembleDebug
```

**Result:** `BUILD SUCCESSFUL` ✅

The debug APK was generated at:

```
app/build/outputs/apk/debug/app-debug.apk
```

APK size: approximately **17 MB**.

---

### 📱 Step 2 — ADB Setup & Device Configuration

Initial attempt to run ADB revealed it was not in the system PATH:

```
adb: command not found
```

**Resolution steps:**

1. Located Android SDK installation directory
2. Found `platform-tools/adb.exe` at the correct path
3. Used the direct path to execute ADB commands

---

### 🔓 Step 3 — Physical Device Setup (Redmi 12)

The target device was a **Xiaomi Redmi 12** running Android.

**Configuration required:**

| Step | Action | Result |
|---|---|---|
| Developer Options | Enabled via About Phone → MIUI Version (7 taps) | ✅ Unlocked |
| USB Debugging | Toggled ON in Developer Options | ✅ Enabled |
| ADB Authorization | Accepted "Allow USB Debugging" popup on device | ✅ Authorized |
| Install via USB | Enabled Install via USB permission | ✅ Configured |
| Google Verification | Completed required Google account verification | ✅ Passed |

**ADB Device Detection:**

```bash
adb devices
# Output: ad2bd651    device   ← Redmi 12 successfully detected ✅
```

---

### 📦 Step 4 — APK Installation

```bash
adb install app/build/outputs/apk/debug/app-debug.apk
```

**Initial attempt:** ❌ `INSTALL_FAILED_USER_RESTRICTED`

**Root cause:** Install via USB permission was not yet enabled.

**Fix:** Enabled **Install via USB** in Developer Options.

**Second attempt:** ✅ `Success` — APK installed successfully.

The app appeared on the device Home Screen. 🎉

---

### 🐛 Step 5 — Runtime Crash & Debugging

On first launch, the application **crashed immediately**.

**Error encountered:**

```
FATAL EXCEPTION: NullPointerException
at NavGraph.kt
related to: Screen.bottomNavItems
```

**Root cause identified:**

A `listOf()` call in `Screen.kt` was including a `null` navigation entry, which was being passed directly into the navigation graph without null safety checks.

**Fix applied:**

```kotlin
// Before (caused NullPointerException)
listOf(...)

// After (null-safe fix)
listOfNotNull(...)
```

This change filtered out any null navigation entries before they reached the navigation graph, eliminating the crash.

---

### 🔄 Step 6 — Rebuild & Reinstall

```bash
./gradlew assembleDebug
# BUILD SUCCESSFUL ✅

adb install app/build/outputs/apk/debug/app-debug.apk
# Success ✅
```

---

### ✅ Step 7 — Successful Launch

The updated APK was reinstalled on the **Redmi 12**.

- USB cable was disconnected.
- The app was launched independently from the device Home Screen.
- The application **opened successfully, navigated correctly, and ran stably** as a standalone app on the physical device. 🚀

## ⚡ Challenges & Solutions

| # | Challenge | Problem Description | Solution Applied | Status |
|---|---|---|---|---|
| 1 | **ADB Not Found** | `adb: command not found` — ADB was not in the system PATH | Located `platform-tools/adb.exe` and used direct path | ✅ Resolved |
| 2 | **Device Not Detected** | `adb devices` showed no connected devices | Enabled USB Debugging and accepted ADB authorization popup on device | ✅ Resolved |
| 3 | **Developer Options Hidden** | Developer Options menu not visible in Settings | Navigated to About Phone → MIUI Version → tapped 7 times to unlock | ✅ Resolved |
| 4 | **Install via USB Restricted** | `INSTALL_FAILED_USER_RESTRICTED` error on APK install | Enabled Install via USB in Developer Options + completed Google verification | ✅ Resolved |
| 5 | **Runtime NullPointerException** | App crashed immediately on launch with NPE from NavGraph | Changed `listOf()` to `listOfNotNull()` in `Screen.kt` to filter null nav entries | ✅ Resolved |
| 6 | **Navigation Null Reference** | Null navigation entry reaching the NavGraph caused fatal crash | Null-safe filtering applied at the source before entries reached navigation | ✅ Resolved |
| 7 | **Rebuild & Reinstall Cycle** | Required full rebuild and reinstallation after each code change | Established systematic `assembleDebug` → `adb install` workflow | ✅ Established |
